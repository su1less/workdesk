# 工作台 · 服务器迁移部署指南

> 按你的服务器定制：**腾讯云轻量应用服务器**（上海五区）
> 实例 `lhins-k716w03w` · Ubuntu 22.04 · **预装 Docker 26** · 公网 IPv4 `111.229.230.130`
>
> 预装了 Docker，所以推荐 **Docker Compose 方式**部署：不污染系统、开机自启、升级只需一条命令。

---

## 方案总览

```
手机/电脑浏览器 ──HTTP──▶ http://111.229.230.130:8765 ──▶ Docker 容器 workdesk
                                                          ├── 静态页面（index.html/js/css）
                                                          ├── 登录 + 数据 API（server.js）
                                                          └── ./data/ ←→ 容器卷（db.json + 密码配置，宿主机持久化）
```

| 迁移项 | 结论 |
| --- | --- |
| 部署方式 | `git clone` → `docker compose up -d --build`（约 2 分钟） |
| 数据迁移 | **无需手动搬**：用存有最新数据的设备打开新网址登录，本地数据自动上传服务器 |
| 老师只读分享 | ✅ 支持：设置 → 🔗 只读分享，实时刷新（比 GitHub 模式还快） |
| 文档图片 | ✅ 原图直传服务器 `assets/`（不压缩，老师可下载论文级原图） |
| HTTPS | 先用 IP:端口（有明文风险提示）；有已备案域名后一键升级 Caddy |

## 第一步 · SSH 登录服务器

控制台显示实例**未绑定密钥**，两种方式任选：

- **重置密码**（简单）：控制台 → 实例 → 「重置密码」→ 设 root/ubuntu 密码 → 重启生效
- **绑定密钥**（更安全，推荐）：控制台 → 密钥对 → 创建/导入 → 绑定实例

然后本机连接：

```bash
ssh root@111.229.230.130        # 或 ubuntu@111.229.230.130（取决于镜像默认用户）
```

## 第二步 · 放行 8765 端口（两处都要）

1. **腾讯云控制台防火墙**（轻量服务器特有，必须做）：控制台 → 实例 → 防火墙 → 添加规则
   - 协议 `TCP`，端口 `8765`，来源 `0.0.0.0/0`（所有人可访问；也可先只填自己的 IP 更安全）
2. **系统内 ufw**（Ubuntu 镜像通常默认未启用，确认一下）：

```bash
ufw status                 # inactive 就不用管；active 则执行下行
ufw allow 8765/tcp && ufw reload
```

## 第三步 · 上传代码（两条路任选）

**路 A · git clone（推荐，方便以后升级）**

```bash
apt update && apt install -y git      # Ubuntu 一般已带
cd /opt && git clone https://github.com/su1less/workdesk.git
cd workdesk
```

> 服务器在国内，clone GitHub 偶尔慢/超时。若失败两次，改用你在 USTC GitLab 的镜像：
> `git clone https://git.lug.ustc.edu.cn/<你的用户名>/workdesk.git`（校内镜像在国内快得多）

**路 B · 本地打包上传（不依赖 git）**

在本机 `E:\cc_work\工作台` 目录执行（Git Bash）：

```bash
cd /e/cc_work && tar --exclude=工作台/.git --exclude=工作台/data -czf workdesk.tar.gz 工作台
scp workdesk.tar.gz root@111.229.230.130:/opt/
ssh root@111.229.230.130 "cd /opt && tar xzf workdesk.tar.gz && mv 工作台 workdesk"
```

## 第四步 · 构建并启动

```bash
cd /opt/workdesk
docker compose up -d --build
```

**如果 `docker pull node:20-alpine` 卡住/超时**（国内拉 Docker Hub 不稳），先配镜像加速再重试：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }
EOF
systemctl restart docker && docker compose up -d --build
```

## 第五步 · 拿到初始密码并访问

```bash
docker logs workdesk          # 首次启动会打印随机生成的登录密码
```

浏览器打开 **http://111.229.230.130:8765**，输入密码登录即可。

## 第六步 · 数据迁移（从 GitHub 模式搬过来）

**零手动操作，顺序很重要**：

1. 找到**数据最新的那台设备**（一般是日常使用的电脑），浏览器打开 `http://111.229.230.130:8765` 并登录
2. 它会检测到服务器是空的，**自动把本机数据完整上传**（几秒完成，右下角有同步提示）
3. 其他设备同样打开新网址登录，自动拉取最新数据
4. 确认无误后，旧地址（GitHub Pages）可以停用；**建议保留 GitHub 仓库作为异地备份**（数据历史都在 commit 里）

注意：

- 上传的是浏览器内的**明文数据**，服务器端 `data/db.json` 不再加密（GitHub 模式的加密是为了公开仓库，服务器模式靠登录密码 + 服务器安全保护），备份 `data/` 目录即可
- 一台设备同一时间只跟一个源同步。切换期间别再打开旧 GitHub 页面做编辑，避免两边分叉

## 日常运维

| 操作 | 命令 |
| --- | --- |
| 改登录密码 | `docker exec -it workdesk node server.js --set-password 新密码` |
| 升级到新版本 | `cd /opt/workdesk && git pull && docker compose up -d --build`（数据不丢） |
| 看运行日志 | `docker logs -f workdesk` |
| 重启 / 停止 | `docker restart workdesk` / `docker compose down` |
| **备份全部数据** | `tar czf /root/workdesk-backup-$(date +%F).tar.gz /opt/workdesk/data/ /opt/workdesk/assets/`（数据 + 文档图片） |

自动每日备份（保留 7 天）：

```bash
cat > /etc/cron.daily/workdesk-backup <<'EOF'
#!/bin/sh
tar czf /root/workdesk-backup-$(date +%F).tar.gz /opt/workdesk/data/ /opt/workdesk/assets/
find /root -name 'workdesk-backup-*.tar.gz' -mtime +7 -delete
EOF
chmod +x /etc/cron.daily/workdesk-backup
```

## HTTPS（有了已备案域名再做）

现在用 `IP:8765` 是 HTTP 明文——登录密码在网络上可被截获，个人短期使用可接受，**尽快配域名**。注意：国内服务器 80/443 端口必须**已备案域名**才能正常对外服务。

有域名后，在 `docker-compose.yml` 旁新建 `Caddyfile`：

```
desk.你的域名.com {
    reverse_proxy workdesk:8765
}
```

并在 `docker-compose.yml` 追加（与 workdesk 同级缩进）：

```yaml
  caddy:
    image: caddy:2
    container_name: workdesk-caddy
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy-data:/data
    restart: unless-stopped
volumes:
  caddy-data:
```

然后控制台防火墙放行 80/443，`docker compose up -d` 即自动申请证书。

## 备选 · 不用 Docker 直接跑（Node + systemd）

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs
cat > /etc/systemd/system/workdesk.service <<'EOF'
[Unit]
Description=Workbench
After=network.target
[Service]
WorkingDirectory=/opt/workdesk
Environment=PORT=8765
ExecStart=/usr/bin/node server.js
Restart=always
[Install]
WantedBy=multi-user.target
EOF
systemctl enable --now workdesk
journalctl -u workdesk -n 20 --no-pager    # 查看初始密码
```

## 安全清单

- [ ] SSH 改用密钥登录，禁用密码（`/etc/ssh/sshd_config` 设 `PasswordAuthentication no`）
- [ ] 防火墙 8765：需要老师访问时保持来源 `0.0.0.0/0`；不需要分享时可收窄为自己的常用 IP
- [ ] 登录密码足够长（服务器有 6 次错误锁 15 分钟的保护）
- [ ] 定期备份 `data/` 并下载一份到本地

## 与 GitHub 模式的差异

| 能力 | GitHub Pages 模式 | 本服务器模式 |
| --- | --- | --- |
| 同步延迟 | 写入 3s + Pages 部署数分钟 | 0.7s 推送 / 25s 拉取，基本实时 |
| 老师只读分享（网址+密码） | ✅ 分享密码解密 share.json，更新延迟几分钟 | ✅ 实时只读（30 秒轮询），停止分享立即生效 |
| 文档配图 | 原图存仓库 `assets/`，老师可下载论文级原图 | 原图存服务器 `assets/`（compose 已挂载持久化），同样可下载 |
| 单文件大小限制 | Contents API 约 1MB | 上传请求上限 32MB |
| 可用性 | 依赖 GitHub 可访问性 | 只依赖你自己服务器 |

**迁移后开启老师访问**：设置 → ☁ 云端同步 → 🔗 只读分享 → 设分享密码，把 `http://111.229.230.130:8765` 和密码发给老师即可。老师打开网址点「👁 只读查看工作安排」输入密码——只读、实时、可下载原图。注意防火墙需保持 8765 对老师开放（来源 `0.0.0.0/0`，或填老师的常用 IP）。

> 历史图片自动迁移：GitHub 模式时期的文档图片存在仓库 `assets/` 目录，`git clone` 部署时随代码一起到服务器（compose 已把 `./assets` 挂载进容器），无需额外操作。
