# ⚡ 工作台 · My WorkDesk

一个纯本地运行的智能任务工作台：整理日 / 周 / 月任务、追踪进度、导入 Markdown 计划、每天早晨的秘书晨报，以及突发日程的自动重排。

## 快速开始

**方式一（本地单机）**：直接双击 `index.html` 用 Chrome / Edge 打开即可，无需安装任何东西，数据保存在浏览器本地（localStorage）。

**方式二（云端多设备，推荐）**：用自带的零依赖 Node 服务器部署，密码门禁 + 数据存服务器，多设备看到同一份数据，清浏览器缓存不丢数据：

```bash
# 需要 Node 14+，无需 npm install
node server.js
# 首次启动会在控制台打印自动生成的初始访问密码，例如：2714-bd9c-55fa

node server.js --set-password 你的新密码   # 修改密码
PORT=9000 node server.js                  # 自定义端口
WORKBENCH_PASSWORD=xxx node server.js     # 用环境变量当密码（适合托管平台）
```

浏览器访问 `http://服务器IP:8765`，输入密码进入。手机 / 公司 / 家里打开同一网址登录，看到同一份数据。

> 同一部署下，`file://` 打开、静态托管、node 服务三种环境自动适配；只有检测到 node 后端时才启用登录与云同步。

### 部署到 GitHub Pages（免费 + 数据同步）

GitHub Pages 只能托管静态文件，`server.js` 无法运行，但内置的 **GitHub 同步**可以用你自己的仓库当数据库，效果等同云端版：多设备一致、清缓存不丢、免费、自带版本历史（每次修改自动 commit）。

**步骤：**

1. 把本目录推到一个仓库。**公开仓库**可以直接用 GitHub Pages；**私有仓库**见下方"私有仓库方案"：

   ```bash
   git init
   git add .
   git commit -m "工作台"
   git branch -M main
   git remote add origin https://github.com/你的用户名/仓库名.git
   git push -u origin main
   ```

2. 仓库 **Settings → Pages** → Source 选 *Deploy from a branch*，分支 `main`、目录 `/ (root)`，保存。几分钟后访问 `https://你的用户名.github.io/仓库名/`

3. 生成访问令牌：GitHub → **Settings → Developer settings → Fine-grained tokens → Generate new token**
   - Repository access 选 *Only select repositories* → 勾选该仓库
   - Permissions → Repository permissions → **Contents: Read and write**

4. 打开你的 Pages 网址 → ⚙️ 设置 → ☁ 云端同步 → **配置 GitHub 同步**：填仓库（`用户名/仓库名`）、分支、令牌，**强烈建议设置加密口令** → 验证并保存

5. 其他设备：打开同一网址，重复第 4 步（加密口令须一致）

**私有仓库方案（更私密，同样免费）：**

GitHub 免费账户的 Pages 只对公开仓库开放，但页面托管可以交给其他平台，数据照样存私有仓库：

1. 仓库设为 **Private**，照常完成上面第 3~5 步（GitHub 同步对私有仓库完全支持）
2. 页面托管改用 **Vercel / Netlify / Cloudflare Pages**（免费版都支持从私有仓库自动部署静态站）：新建项目 → 导入该仓库 → 框架选 *Other*，输出目录为根目录 → 部署后用平台分配的网址访问
3. 建议在托管平台配置**忽略构建**（Vercel: *Ignored Build Step*，Netlify: build ignore），让只有 `data/` 变化的数据同步 commit 不触发重新部署

私有仓库中数据文件本身外界不可见，加密口令变为可选（仍建议设置，作为令牌泄露时的第二道防线）。若愿意付费（GitHub Pro $4/月），私有仓库也可以直接开 Pages，省去第二个平台。

**只读分享（把工作安排发给老师/导师查看）：**

想让别人通过 **网址 + 一个密码** 只读查看你的工作安排？云端同步（GitHub 或自建服务器）配置好后：

设置 → ☁ 云端同步 → **🔗 只读分享** → 设置分享密码 → 开启。然后把网址和分享密码发给老师即可：

- 老师打开网址 → 点「👁 只读查看工作安排」→ 输入分享密码 → 看到你的任务、日程、文献与报告的**只读视图**：不能修改任何内容（所有编辑操作被拦截），数据自动刷新，本机记住密码（你改分享密码后立即失效）
- 文档里的插图为**原图**：老师点击图片即可在新标签页打开、下载原图（论文级分辨率）
- 自建服务器模式：数据**实时**刷新（30 秒轮询，站长改完老师马上能看到）；GitHub 模式：更新延迟几分钟（Pages 部署耗时），实现为仓库里一份用分享密码加密的 `data/share.json`
- 注意：分享数据对老师**全量可见**（所有任务与文献内容），请自行斟酌分享范围；服务器模式未配 HTTPS 前密码为明文传输
- 停止分享：同一弹窗里点「停止分享」，旧密码立即失效

**网页门禁（可选的另一层）：**

设置 → ☁ 云端同步 → **🔒 网页门禁** 可再设一个"门禁密码"：输入它进入的是**本地空白模式**（不显示你的数据），主要用来防止完全无关的路人占用界面。你的常用设备（已配置同步）会自动跳过所有密码页。

> 三个密码各司其职：**加密口令**（保护数据机密）、**分享密码**（给老师只读查看）、**门禁密码**（路人进入空白模式）。修改任一密码都只影响对应能力。

**说明与限制：**

- 修改后约 3 秒自动提交到仓库；每 60 秒及窗口聚焦时拉取其他设备变更；多设备同时编辑时后保存者优先
- 数据文件默认 `data/db.json`，由 GitHub API 直接写入仓库（不受 .gitignore 影响），在仓库的 commit 历史里可以看到每次变更
- **加密口令**：数据用 AES-GCM 加密后才上传（密文入库），公开仓库也安全；不加密则任何人都可能在仓库里直接看到数据内容。令牌与口令只保存在各设备浏览器本地
- 国内直连 `github.io` 可能不稳定，若经常无法访问，建议改用下述云服务器 / 托管平台方案

### 部署到哪里（选一种）

| 场景 | 做法 |
| --- | --- |
| GitHub Pages（免费） | 见上一节"部署到 GitHub Pages"，静态页面 + 仓库当数据库 |
| 云服务器 / VPS | **推荐 Docker**：`docker compose up -d --build`，详见 [deploy/服务器部署指南.md](deploy/服务器部署指南.md)（按腾讯云轻量 Ubuntu + Docker 定制的逐步操作 + 数据迁移步骤）；或裸跑 `node server.js` 配 systemd/pm2 |
| 家里的电脑 | 同上 + 内网穿透（Cloudflare Tunnel / Tailscale）即可在外访问 |
| 免费托管平台 | 支持 Node 的平台（如 Render / Railway / Fly.io）直接跑 `server.js`，用 `WORKBENCH_PASSWORD` 环境变量设密码 |

**HTTPS 必须配**（否则密码在网络上明文传输）。最简单是 Caddy，两行自动申请证书：

```
你的域名.com {
    reverse_proxy 127.0.0.1:8765
}
```

### 安全机制

- 未登录访问只能看到登录页，工作台界面与数据完全不可见；
- 密码 scrypt 加盐哈希后存储在 `data/server-config.json`，明文不落盘；
- 登录令牌为 HMAC 签名、30 天有效；同 IP 连续 6 次密码错误锁定 15 分钟；
- 只读分享使用独立令牌（与站长令牌严格分离，无任何写权限），分享验证同样限速；
- `assets/`（文档图片）为公开静态目录，文件名含随机后缀不可枚举；
- `data/`（你的数据与密码哈希）整个目录禁止一切外部 HTTP 访问，路径穿越已拦截；
- 数据文件 `data/db.json`，定期复制一份即完成备份（页面「设置」里也可导出 JSON）。

### 同步机制说明

任何修改会在 0.7 秒内推送到服务器；每 25 秒及窗口聚焦时自动拉取其他设备的变更。粒度为整库覆盖（后保存者优先），单人日常使用足够；避免两台设备**同时**编辑即可。

## 快速添加语法

顶栏输入框直接输入，回车创建：

```
写周报 14:00-15:00 !高 #产品 明天
```

| 语法 | 含义 | 示例 |
| --- | --- | --- |
| `HH:MM-HH:MM` | 时间块 | `14:00-15:30` |
| `@2026-10-24` / `@10-24` | 指定日期 | `@10-28` |
| `今天 / 明天 / 后天 / 周三 / 下周五` | 相对日期 | `明天` |
| `P0 P1 P2` / `!高 !中 !低` / `[高]` | 优先级 | `P0` |
| `40%` / `进度:40` | 进度 | `60%` |
| `~2h` / `90分钟` | 时长（配合开始时间自动算结束） | `~2h` |
| `#标签` | 标签（可多个） | `#研发` |
| `[固定]` | 固定日程（不参与自动调整） | `[固定]` |
| `【日】【周】【月】` | 任务层级 | `【周】` |

## Markdown 计划文档格式

导入页支持文件上传 / 拖拽 / 粘贴，解析前可逐项修改，示例：

```markdown
# 项目冲刺计划
## 2026-11-02 ~ 2026-11-08 本周安排     ← 日期区间：区间内任务自动按天分配
- [ ] 完成登录模块开发 !高 ~4h
- [x] 需求评审会议 14:00-15:30 [固定]
  - 复现步骤见 issue #123              ← 缩进行并入上一条任务的备注
- [ ] 修复支付回调 bug P0
## 每日任务                              ← 自动识别为"今日"
- [ ] 09:30-10:00 每日站会 [固定]
## 本周任务                              ← 识别为周任务
- [ ] 完成联调测试 60% #测试
## 本月目标                              ← 识别为月目标
- [ ] 发布 v2.1 版本 20%
```

也支持管道表格（表头含 `任务/日期/优先级/进度/状态/备注/类型` 即可识别）。

## 周报月报（文档写作）

侧边栏「📝 周报月报」：新建周报/月报后进入编辑器——左侧 Markdown 编辑、右侧实时预览（手机上是"编辑/预览"切换）。所有修改自动保存并随云端同步；只读分享的访客也能查看这些文档。

- **图片**：工具栏 🖼 选择本地图片。GitHub / 自建服务器模式下**原图直传 `assets/` 目录**（不压缩，保留论文级分辨率），文档只存网址；预览中**点击图片可在新标签打开原图**，分享对象可直接下载原始分辨率。本地模式自动压缩（最长边 1000px）后内嵌。注意：GitHub 公开仓库中图片文件可见，请勿放敏感截图
- **LaTeX 公式**：`$E=mc^2$` 行内、`$$...$$` 块级，由本地内置的 KaTeX 渲染（无外网依赖，离线可用）
- **代码块**：```` ```语言 ```` 围栏，工具栏 `</>` 一键插入
- **工具栏**：标题/粗斜体/删除线/列表/任务清单/公式/图片/链接/表格/引用，均在光标处插入
- 与「进度报告」联动：自动生成的周报/月报可点「📝 存为文档」转为可编辑文档，再补充截图与公式
- 注意：本地模式图片为内嵌存储，图片较多时数据体积会增大（GitHub 同步的单文件上限约 1MB）——云端模式图片走 `assets/` 独立文件，无此顾虑

## 文献管理

侧边栏「📚 文献管理」提供完整的文献阅读追踪：

- **文献条目**：标题 / 作者 / 年份 / 类型（论文·书籍·文章·其他）/ 期刊·会议 / DOI / 链接 / 标签 / 摘要 / 阅读笔记
- **阅读状态**：想读 → 在读 → 已读（卡片上一键循环切换，"已读"自动记录完成时间）；在读条目带阅读进度条
- **评分**：1–5 星
- **筛选与排序**：关键词搜索、按状态/类型/标签筛选，按添加时间/年份/评分排序
- **BibTeX 导入**：点击「导入 BibTeX」上传 `.bib` 文件（Zotero / EndNote / Google Scholar 导出）或直接粘贴，解析后可逐项修改再入库；自动识别 `@article / @inproceedings / @book` 等类型、期刊/会议、DOI、关键词、arXiv eprint 链接
- **BibTeX 导出**：一键导出整个文献库为 `.bib`
- **与任务联动**：每篇文献卡片上有「＋今日」「＋本周」按钮，一键生成《阅读〈文献标题〉》任务（自动带上作者/出处备注与 #文献 标签）；仪表盘展示在读文献进度，晨报提醒在读清单，周报/月报自动生成「文献阅读」章节（含本期已读与在读进度）

## 突发日程的自动调整规则

1. **固定日程**（会议等 `固定` 项）永远不会被移动，作为占用块；
2. 与突发时段冲突的**可调任务**按原时间排序，依次在工作时段（默认 07:00–23:00，可在设置中修改）内寻找新空档：优先当日突发日程之后，放不下则顺延到后续几天（最多 7 天）；
3. 已移动的任务占用新位置，避免互相堆叠；
4. 与突发日程冲突的**固定日程**无法自动调整，会给出提示请人工协调；
5. 每次调整都会在任务上留下「已调整」标记，并写入周报/月报的「突发日程记录」章节。

## 数据与隐私

- 云端模式：数据存在服务器 `data/db.json`，浏览器 localStorage 仅作缓存；备份 = 复制该文件
- 本地模式：所有数据仅保存在本机浏览器 localStorage，不上传任何服务器
- 「设置」中支持导出 / 导入 JSON 备份、恢复演示数据、清空全部数据；云端模式另有"退出登录（此设备）"
